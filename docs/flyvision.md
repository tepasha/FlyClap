# FlyVision — оптичні «очі» для FlySonar (ESP32-CAM)

Режим, у якому турель бачить **мошку 1–3 мм** і може стріляти по цілі в польоті. Raspberry Pi не потрібен: зір рахує ESP32 за ~5 мс на кадр, а Arduino лишається контролером реального часу.

```
 ┌───────────── LED-панель A4 (підсвічений фон) ─────────────┐
 │                  · ← мошка = темна точка                  │
 └───────────────────────────────────────────────────────────┘
          ▲ ~30 см                      ▲
     [ESP32-CAM] ──UART 115200──► [Arduino] ──► серви pan/tilt + клапан
      зір, трекер,  "A pan tilt fire"      ARM, кулдаун, блокування,
      калібрування                          таймінг пострілу
```

## Чому саме так

- **Підсвічений фон.** Комаха на світлій панелі дає чорну тінь з величезним контрастом, без складного розпізнавання. Так працюють і промислові оптичні «паркани» для комарів. Світла панель ще й сама приваблює комах, і вони **сідають на неї**. Це найлегші цілі, і для них немає паралакса (див. нижче).
- **Роздільність.** QVGA 320×240 на полі шириною ~30 см дає ~1 мм на піксель, тобто мошка займає 2–4 пікселі. Алгоритм ловить плями від 2 пікселів.
- **Камера нерухома, окремо від турелі.** Калібрування «піксель → кути серв» робиться тестовими пострілами, тож зміщення сопла й провисання струменя входять у модель автоматично.

## Що купити (до комплекту FlySonar)

| Деталь | К-сть | Примітка |
|---|---|---|
| ESP32-CAM (AI-Thinker, OV2640, 4 МБ PSRAM) | 1 | Найдешевша. Або ESP32-S3-WROOM CAM (Freenove) / ESP32-S3-EYE |
| Програматор ESP32-CAM-MB (USB) | 1 | Для AI-Thinker, у S3-плат USB вбудований |
| LED-планшет для копіювання A4, живлення USB 5 В | 1 | Фон. A3 теж можна, але тоді ~1,3 мм/піксель |
| Прозора плівка або оргскло 2 мм на панель | 1 | Захист від бризок, протирається |
| Кронштейн для камери | 1 | Жорстко, камера не повинна зсуватись після калібрування |
| Темний маркер (чорна наліпка ∅3–5 мм на прозорій плівці або на дротинці) | 1 | Для калібрування |

Бажано для точності:
- **Клапан + обприскувач** замість помпи (`SHOOTER_VALVE 1`), див. [flysonar.md](flysonar.md#ствол-помпа-чи-клапан-shooter_valve).
- **Цифрові мікросерво** з малою мертвою зоною (напр. EMAX ES08MD II) замість MG90S.
- **Латунне сопло-розпилювач 0,3–0,5 мм**: конус 2–4 см прощає залишкову похибку.

## Підключення

| ESP32 | Куди |
|---|---|
| GPIO14 (TX) | D0 (RX) Arduino |
| GND | GND Arduino (обов'язково) |
| 5V | окремий 5 В ≥1 А (DC-DC), **не** від 5V Arduino |

- Лінія односпрямована, ESP32 → Arduino. 3,3 В логіки ESP32 Arduino читає як HIGH, дільник не потрібен.
- На D0 Arduino також сидить USB-перехідник. **На час прошивки Arduino від'єднуйте провід від D0.** Під час роботи нічого не надсилайте з монітора порту Arduino: лог з Arduino (TX) читати можна.
- На AI-Thinker GPIO14 — лінія SD-картки, картку не вставляйте.

## Прошивка

| Що | Середовище PlatformIO |
|---|---|
| ESP32-CAM AI-Thinker | `pio run -e flyvision -t upload` |
| ESP32-S3-EYE / Freenove S3 CAM | `pio run -e flyvision_s3 -t upload` |
| Arduino (Uno / Nano) | `pio run -e flysonar_camera -t upload` / `flysonar_camera_nano` |

Arduino IDE: плата «AI Thinker ESP32-CAM» (PSRAM увімкнено), модель камери обирається `#define` на початку `flyvision.ino`. Для Arduino на початку `flysonar.ino` поставте `TARGET_SOURCE_CAMERA 1`.

> ⚠️ Прошивку ESP32 перевірено лише статично: сигнатури API звірено з `esp32-camera` та `arduino-esp32`, синтаксис перевірено компілятором на заглушках, алгоритм зору протестовано на ПК (`tools/run_tests.sh`). Повну збірку під ESP32 у середовищі розробки виконати не вдалося, тому перша збірка у вас може потребувати дрібних правок під версію ядра.

## Калібрування камери

Монітор порту **ESP32** на 115200. Команди — одна клавіша:

| Клавіша | Дія |
|---|---|
| `m` | увімкнути/вимкнути режим калібрування |
| `a d w s` | довернути турель на 0,5° (великі `A D W S` — на 5°) |
| `f` | тестовий постріл 40 мс (тумблер ARM має бути увімкнений) |
| `c` | записати точку: пляма маркера ↔ поточні кути |
| `u` | скасувати останню точку |
| `v` | розрахувати й зберегти (≥3 точки) |
| `b` | перевчити фон |
| `t` | стріляти також по цілях у польоті (з упередженням) |
| `p` | стан: fps, калібрування, ціль, швидкість |

Порядок:
1. Увімкнути панель, прибрати все з поля. Через 2,5 с після старту експозиція фіксується і фон вивчається сам (або натисніть `b`).
2. `m`. Кнопками `a d w s` навести турель приблизно в кут поля.
3. `f`: на плівці з'явиться мокра пляма. Покладіть маркер точно на неї, тоді `c` (у кадрі має бути рівно одна темна точка).
4. Повторити для 4–6 точок по всьому полю: кути й центр. Точки не мають лежати на одній прямій.
5. `v`. ESP32 покаже найгіршу залишкову похибку в градусах. Приберіть маркер, протріть плівку, натисніть `b`, потім `m` (вихід у бойовий режим).

## Як працює

1. **Фон** — ковзне середнє кадрів. Під темними плямами фон не оновлюється, тому муха, що сіла, не «розчиняється» у фоні.
2. **Маска.** Піксель вважається темною плямою, якщо він на панелі (фон ≥ `backdropMin`) і темніший за фон на `darkDelta`.
3. **Плями.** Зв'язні області від 2 пікселів і не більші за 14×14 — цілі. Більші, або понад 400 темних пікселів у кадрі (рука, кіт, людина), дають команду `B`: Arduino 3 с не стріляє.
4. **Трекер альфа-бета** згладжує позицію й оцінює швидкість у пікселях/с.
5. **Приціл.** Ціль повільніша за 15 пікс/с вважається нерухомою, і приціл береться в поточну точку. По цілі в польоті приціл береться в точку, де вона буде через `LATENCY_MS` (70 мс: кадр + обробка + доворот + політ струменя), але лише з увімкненим `t`.
6. **Дозвіл стріляти:** ціль підтверджена ≥5 кадрів поспіль, у поточному кадрі видна, великого об'єкта не було 3 с.
7. Arduino додатково перевіряє ARM, «серво доїхало», свіжість команди (≤150 мс), серію (3 постріли) і кулдаун.

## Обмеження (чесно)

- **Паралакс.** Камера бачить 2D. Калібрування зроблене в площині панелі, тож ціль на відстані Δ перед панеллю дає похибку ≈ (відстань камера↔сопло) × Δ / (відстань до панелі). Ставте камеру якомога ближче до осі турелі (3–5 см). Найточніше влучання — по комахах, що сіли на панель. Тому біля панелі варто покласти приманку (сироп, оцет).
- **Політ.** OV2640 дає ~25–30 кадрів/с, повна затримка ~70–90 мс. Мошка за цей час зміщується на 3–8 см, і упередження компенсує це лише для рівного польоту. Для цілей у польоті використовуйте розпилювач, а не голку.
- **Змазування.** OV2640 має «біжучий» затвор, тож швидка комаха виходить злегка розмазаною. На центроїд це майже не впливає.
- **Освітлення.** Фон має бути **стабільно** яскравим. Пряме сонце на панель чи миготливі лампи дають хибні плями. Експозиція фіксується після старту: якщо світло в кімнаті змінилося, перезавантажте ESP32 або натисніть `b`.
